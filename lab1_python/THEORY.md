## 1. Симметричные положительно определённые матрицы

**Определение.** Вещественная матрица $A \in \mathbb{R}^{n \times n}$ называется симметричной положительно
определённой (СПО), если $A = A^T$ и $x^T A x > 0$ для любого $x \neq 0$.

**Критерии** (для симметричной $A$ равносильны):
1. все собственные числа $\lambda_i(A) > 0$;
2. критерий Сильвестра: все ведущие главные миноры $\Delta_1, \dots, \Delta_n$ положительны;
3. существует разложение Холецкого $A = LL^T$ с $l_{ii} > 0$;
4. $A = B^T B$ для некоторой невырожденной матрицы $B$.

**Свойства, которые полезно помнить:**
- $a_{ii} = e_i^T A e_i > 0$;
- $|a_{ij}| < \sqrt{a_{ii} a_{jj}}$ при $i \neq j$ (минор 2×2 из строк и столбцов $i, j$ положителен), поэтому
  наибольший по модулю элемент лежит на диагонали;
- любая главная подматрица и любое дополнение Шура СПО-матрицы — тоже СПО; $A^{-1}$ — СПО;
- число обусловленности в спектральной норме $\kappa_2(A) = \lambda_{\max}/\lambda_{\min}$.

**Где возникают СПО-матрицы** (связь с п. 1 списка литературы — «учебники, в которых есть неявная разностная схема»):
- неявные разностные схемы для уравнений теплопроводности и Пуассона. Например, чисто неявная схема для
  $u_t = a^2 u_{xx}$:
  $$\frac{y_i^{n+1} - y_i^{n}}{\tau} = a^2 \, \frac{y_{i-1}^{n+1} - 2y_i^{n+1} + y_{i+1}^{n+1}}{h^2}$$
  на каждом шаге по времени требует решать СЛАУ с матрицей $I + \frac{a^2 \tau}{h^2}\,\mathrm{tridiag}(-1, 2, -1)$ —
  она симметрична, её собственные числа $\geq 1$, т. е. она СПО. В двумерном и трёхмерном случаях матрица ленточная
  (пяти- и семидиагональная), и для неё применяют метод Холецкого (в русской литературе — **метод квадратного корня**).
  Важно: матрица одна и та же на всех шагах по времени, меняется только правая часть, поэтому разложение
  делается один раз;
- метод наименьших квадратов (нормальные уравнения $A^T A x = A^T f$), метод конечных элементов (матрицы
  жёсткости), ковариационные матрицы, гессианы в методах оптимизации.

## 2. Разложение Холецкого (точечный алгоритм)

**Теорема.** $A$ — СПО $\iff$ существует, и притом единственная, нижнетреугольная матрица $L$ с положительной
диагональю, такая что $A = LL^T$.

*Доказательство (индукция по $n$).* Запишем
$$
A = \begin{pmatrix} a_{11} & w^T \\ w & B \end{pmatrix}
  = \begin{pmatrix} l_{11} & 0 \\ l & L_{22} \end{pmatrix}
    \begin{pmatrix} l_{11} & l^T \\ 0 & L_{22}^T \end{pmatrix}.
$$
Отсюда $l_{11} = \sqrt{a_{11}}$ (а $a_{11} > 0$), $l = w / l_{11}$ и $L_{22} L_{22}^T = B - w w^T / a_{11} = S$.
Дополнение Шура $S$ — СПО: для $y \neq 0$ возьмём $x = (-w^T y / a_{11},\; y)$, тогда $x^T A x = y^T S y > 0$.
По предположению индукции $S = L_{22} L_{22}^T$ единственным образом; $l_{11} > 0$ и $l$ определяются однозначно.
Обратно, если $A = LL^T$ с невырожденной $L$, то $x^T A x = \|L^T x\|_2^2 > 0$. ∎

Условие $l_{ii} > 0$ нужно именно для единственности: смена знака любого столбца $L$ не меняет $LL^T$.

**Расчётные формулы.** Из поэлементного сравнения $a_{ij} = \sum_{k=1}^{j} l_{ik} l_{jk}$ при $i \geq j$:
$$
l_{jj} = \sqrt{a_{jj} - \sum_{k=1}^{j-1} l_{jk}^2}, \qquad
l_{ij} = \frac{1}{l_{jj}} \Big( a_{ij} - \sum_{k=1}^{j-1} l_{ik} l_{jk} \Big), \quad i > j.
$$
Суммы — это **скалярные произведения** уже найденных частей строк $i$ и $j$ матрицы $L$; отсюда название формы
алгоритма «через скалярные произведения».

**Трудоёмкость.** Для столбца $j$ вычисляются $n - j + 1$ скалярных произведений длины $j - 1$, т. е.
$(j-1)(n-j+1)$ умножений и столько же сложений. Сумма по $j$:
$\sum_{j=1}^{n} (j-1)(n-j+1) \approx n^3/6$. Итого:
- $\approx n^3/6$ умножений $+$ $n^3/6$ сложений $=$ **$n^3/3$ операций с плавающей точкой**;
- $n$ квадратных корней и $n(n-1)/2$ делений — это $O(n^2)$, на фоне $n^3$ несущественно.

Для сравнения: LU-разложение (метод Гаусса) — $2n^3/3$ операций. Выигрыш вдвое — за счёт симметрии.

**Память:** достаточно нижнего треугольника, $n(n+1)/2$ чисел; $L$ можно записывать на место $A$.

**Решение СЛАУ** $Ax = f$: $LL^T x = f \Rightarrow Ly = f$ (прямой ход), $L^T x = y$ (обратный ход) — по $n^2$
операций. Разложение выполняется один раз для любого числа правых частей. Попутно $\det A = \prod_i l_{ii}^2$.

**Если $A$ не СПО**, то на некотором шаге подкоренное выражение окажется $\leq 0$ и алгоритм оборвётся.
Поэтому попытка разложения Холецкого — самый дешёвый практический тест положительной определённости.
В `cholesky_ref.py` в этом случае выбрасывается `ValueError`.

**Родственные разложения:** $LDL^T$ (без квадратных корней: $A = \tilde L D \tilde L^T$, у $\tilde L$ единичная
диагональ, $L = \tilde L D^{1/2}$); для симметричных незнакоопределённых матриц — $LDL^T$ с выбором главного
элемента (Банч — Кауфман). Метод Холецкого — это метод Гаусса без выбора главного элемента, применённый к СПО-матрице
с симметричной нормировкой.

**Почему не нужен выбор главного элемента.** Из $a_{ii} = \sum_{k \leq i} l_{ik}^2$ следует $|l_{ik}| \leq \sqrt{a_{ii}}$:
элементы $L$ не могут вырасти (в методе Гаусса без выбора главного элемента такого ограничения нет). Строгое
утверждение об устойчивости — в п. 6.5.

## 3. Формы алгоритма Холецкого (ijk-формы, по Ортеге)

Все варианты алгоритма выполняют одну и ту же операцию
```
a_ij = a_ij − l_ik · l_jk        (k < j ≤ i)
```
в тройном цикле по $i, j, k$. Шесть перестановок циклов дают шесть форм. Число операций у всех одинаковое;
отличаются порядок вычислений, доступ к памяти и тип «векторной» операции во внутреннем цикле.

| Внешний цикл | Смысл | Формы | Внутренний цикл |
|---|---|---|---|
| $k$ | после вычисления столбца $k$ сразу модифицируется вся оставшаяся подматрица: **немедленные модификации** (right-looking, «внешнее произведение») | kij, kji | saxpy (axpy) |
| $j$ | столбец $j$ вычисляется целиком непосредственно перед использованием, все модификации от предыдущих столбцов накапливаются: **отложенные модификации** (left-looking, столбцовый алгоритм) | jki, jik | jki — линейная комбинация столбцов (gaxpy); **jik — скалярные произведения** |
| $i$ | строка $i$ вычисляется по уже найденным строкам (up-looking, «окаймление») | ikj, ijk | ikj — saxpy по строкам; **ijk — скалярные произведения** |

Формы «через скалярные произведения» — те, у которых **самый внутренний цикл по $k$**: ijk и jik.

**Наш вариант:**
- на уровне блоков — блочная форма **jik**: внешний цикл по блочным столбцам $j$, затем по блочным строкам
  $i \geq j$, внутренний — по $k$ (блочное скалярное произведение). Это left-looking алгоритм с отложенными
  модификациями;
- внутри диагонального блока (`cholesky_point`) — точечная форма **ijk**: строка за строкой, каждый элемент
  через `np.dot(L_block[i, :j], L_block[j, :j])`;
- `solve_triangular_right` — прямая подстановка по столбцам блока; сумма $\sum_{k<j} x_k l_{jk}$ считается как
  произведение матрицы на вектор (набор скалярных произведений).

**Почему форма важна для векторных и параллельных вычислений** (это мостик к этапам 2–4):
- скалярное произведение требует **суммирования (редукции)**. На векторной машине и в SIMD это не «чистая»
  векторная операция: нужны частичные суммы и их последующее сложение по **схеме сдваивания** ($\lceil \log_2 n \rceil$
  шагов). Saxpy — полностью векторная операция;
- зато в форме скалярных произведений меньше записей в память: каждый $l_{ij}$ записывается один раз (сумма
  накапливается в регистре), а в формах с немедленными модификациями каждый элемент подматрицы перезаписывается
  $O(n)$ раз;
- при хранении матрицы по строкам (C/C++) форма скалярных произведений читает строки $i$ и $j$ матрицы $L$ —
  непрерывные участки памяти, что хорошо для кэша.

## 4. Блочный алгоритм через блочные скалярные произведения

### 4.1. Формулы

Разобьём $A$ и $L$ на блоки $b \times b$ ($p = \lceil N/b \rceil$ блоков по каждой размерности; если $N$ не делится
на $b$, последний блок меньше). Из $A = LL^T$ для блоков нижнего треугольника ($i \geq j$):
$$
A_{ij} = \sum_{k=0}^{j} L_{ik} L_{jk}^T = \sum_{k=0}^{j-1} L_{ik} L_{jk}^T + L_{ij} L_{jj}^T.
$$

Шаг $j = 0, \dots, p-1$:
1. $\tilde A_{jj} = A_{jj} - \sum_{k<j} L_{jk} L_{jk}^T$, затем точечный Холецкий $\tilde A_{jj} = L_{jj} L_{jj}^T$;
2. для $i = j+1, \dots, p-1$: $\tilde A_{ij} = A_{ij} - \sum_{k<j} L_{ik} L_{jk}^T$, затем $L_{ij}$ из уравнения
   $L_{ij} L_{jj}^T = \tilde A_{ij}$, т. е. $L_{ij} = \tilde A_{ij} L_{jj}^{-T}$.

Почему точечный Холецкий для $\tilde A_{jj}$ не обрывается: $\tilde A_{jj}$ — диагональный блок дополнения Шура
ведущей подматрицы порядка $jb$, а дополнение Шура СПО-матрицы — СПО.

Решение $X L_{jj}^T = B$ (`solve_triangular_right`): поскольку $(XL^T)_{:,j} = \sum_{k \leq j} x_{:,k}\, l_{jk}$,
$$
x_{:,j} = \Big( b_{:,j} - \sum_{k<j} x_{:,k}\, l_{jk} \Big) / l_{jj}, \qquad j = 0, 1, \dots, b-1
$$
— прямая подстановка по столбцам слева направо. Каждая строка $X$ при этом считается независимо от остальных.

### 4.2. Что такое «блочное скалярное произведение»

Обычное скалярное произведение $\sum_k x_k y_k$ обобщается на векторы, «элементы» которых — матрицы $b \times b$:
$$
\sum_{k<j} L_{ik} L_{jk}^T = [L_{i0}\; L_{i1}\; \dots\; L_{i,j-1}] \cdot [L_{j0}\; L_{j1}\; \dots\; L_{j,j-1}]^T,
$$
т. е. произведение блочной строки размера $b \times jb$ на транспонированную блочную строку $jb \times b$.
В терминах BLAS — одна операция GEMM (для диагонального блока — SYRK).

### 4.3. Соответствие BLAS/LAPACK

| Шаг | Операция | Подпрограмма BLAS/LAPACK |
|---|---|---|
| модификация диагонального блока | $A_{jj} - \sum L_{jk}L_{jk}^T$ | SYRK |
| точечный Холецкий блока | $\tilde A_{jj} = L_{jj}L_{jj}^T$ | POTF2 / POTRF2 |
| модификация поддиагональных блоков | $A_{ij} - \sum L_{ik}L_{jk}^T$ | GEMM |
| треугольное решение | $L_{ij} = \tilde A_{ij}L_{jj}^{-T}$ | TRSM |

Эталонная подпрограмма LAPACK `dpotrf` (вариант для нижнего треугольника) устроена именно так: на каждом шаге
SYRK → POTRF2 → GEMM → TRSM, то есть это тот же left-looking алгоритм через блочные скалярные произведения.

### 4.4. Трудоёмкость блочного алгоритма

Блочная организация **не меняет** общее число операций ($\approx N^3/3$), меняется только порядок. Распределение:
- точечный Холецкий диагональных блоков: $p \cdot b^3/3 = N b^2/3$;
- треугольные решения: $\approx p^2/2$ штук по $b^3$ $\Rightarrow N^2 b/2$;
- произведения блоков: всё остальное, $\approx N^3/3$.

При $b \ll N$ практически вся работа — умножения блоков, т. е. операции уровня BLAS-3. (В нашей программе для
диагонального блока вычисляется полное произведение $L_{jk}L_{jk}^T$, а не только его нижняя половина; это
добавляет $O(N^2 b)$ операций и на порядок роста не влияет.)

### 4.5. Зачем блоки, если число операций то же

Причина — **локальность данных** и иерархия памяти (подробно — в теории ЛР 2).
Арифметическая интенсивность (операций на один элемент данных):
- BLAS-1 (dot, axpy): $2n$ операций на $2n$ чисел — $O(1)$;
- BLAS-2 (умножение матрицы на вектор): $2n^2$ на $n^2$ — $O(1)$;
- BLAS-3 (умножение блоков $b \times b$): $2b^3$ на $3b^2$ — $O(b)$.

Блок, загруженный в кэш, используется $O(b)$ раз. Размер блока подбирают так, чтобы три блока помещались в кэш:
$3 \cdot 8 \cdot b^2 \leq C$ байт.

В Python у блоков есть ещё одна роль: операции над блоками выполняются внутри NumPy/BLAS (скомпилированный код),
а интерпретатор делает только $O(p^3)$ итераций вместо $O(N^3)$.

### 4.6. Зависимости по данным и параллелизм (основа для ЛР 3–4)

- $L_{jj}$ зависит от блоков $L_{j0}, \dots, L_{j,j-1}$ (вся блочная строка $j$ слева от диагонали);
- $L_{ij}$ зависит от $L_{ik}, L_{jk}$ ($k < j$) и от $L_{jj}$;
- **при фиксированном $j$ все $L_{ij}$, $i > j$, независимы**: каждый пишет в свой блок и только читает уже готовые
  блоки — это естественный параллельный цикл;
- слагаемые блочного скалярного произведения $L_{ik}L_{jk}^T$ тоже независимы, но складываются в один блок:
  это **редукция**, и при наивном распараллеливании по $k$ возникает гонка данных;
- модификации $\tilde A_{ij}$ (включая $i = j$) от $L_{jj}$ **не зависят** — от него зависит только финальное
  треугольное решение. Значит, можно параллельно посчитать все $\tilde A_{ij}$, $i \geq j$, затем
  факторизовать $\tilde A_{jj}$, затем параллельно решить треугольные системы;
- внешний цикл по $j$ последовательный (блочный столбец $j$ нужен всем следующим), длина критического пути — $O(p)$
  шагов;
- на шаге $j$ имеется $p - j - 1$ независимых задач — к концу их становится меньше, чем потоков (дисбаланс нагрузки).

## 5. Тестовая задача

**Метод «заданного решения».** Выбираем заранее известный фактор $L$ и аналитически вычисляем $A = LL^T$;
тогда точное решение известно, и можно измерить фактическую погрешность (а не только невязку).

$$
L^{точн}_{ij} = \begin{cases} 2, & i = j, \\ 1/3, & i > j, \\ 0, & i < j, \end{cases}
\qquad
A_{ij} = \begin{cases} 4 + i/9, & i = j, \\ 2/3 + \min(i,j)/9, & i \neq j \end{cases}
\qquad (i, j = 0, \dots, N-1).
$$

Проверка: $(LL^T)_{ii} = \sum_{k<i} (1/3)^2 + 2^2 = 4 + i/9$; при $i > j$:
$(LL^T)_{ij} = \sum_{k<j} (1/3)^2 + \frac13 \cdot 2 = 2/3 + j/9$.
$L$ невырождена ($\det L = 2^N$), значит $A = LL^T$ — СПО при любом $N$.

**Почему именно $1/3$ и $1/9$.** В двоичной системе $1/3 = 0{,}010101\ldots_2$ — бесконечная периодическая дробь,
поэтому эти числа не представимы точно, и ошибки округления реально возникают. Если взять, например, целочисленную
$L$, все операции будут выполняться точно и погрешность окажется нулевой — исследовать будет нечего.

**Обусловленность тестовой матрицы** (посчитано через `numpy.linalg`):

| $N$ | $\kappa_2(A)$ | $\kappa_2(L)$ | $\lambda_{\min}(A)$ | $\lambda_{\max}(A)$ |
|---|---|---|---|---|
| 8 | 3,2 | 1,8 | 3,36 | 10,8 |
| 32 | 19,7 | 4,4 | 3,36 | 66,4 |
| 64 | 65,7 | 8,1 | 3,36 | 221 |
| 128 | 240 | 15,5 | 3,36 | 806 |
| 256 | 917 | 30,3 | 3,36 | 3 083 |
| 1024 | 14 200 | 119 | 3,36 | 47 730 |

$\lambda_{\min}$ практически не меняется, $\lambda_{\max} \approx N^2/22$, поэтому $\kappa_2(A) \sim N^2$
(примерно $N^2/74$), а $\kappa_2(L) = \sqrt{\kappa_2(A)} \sim N$. Матрица хорошо обусловлена при всех
исследуемых $N$.

**Погрешность и невязка:**
- погрешность $e(N) = \max_{i,j} |L^{числ}_{ij} - L^{точн}_{ij}|$ — прямая (forward) ошибка, требует знания
  точного решения;
- невязка $\max |L^{числ}(L^{числ})^T - A|$ — обратная (backward) ошибка: насколько надо возмутить $A$, чтобы
  найденная $L$ стала её точным фактором. Её можно вычислить всегда;
- малая невязка не гарантирует малую погрешность: $\text{погрешность} \lesssim \kappa \cdot \text{невязка}$.

## 6. Машинная арифметика и погрешности

### 6.1. Формат IEEE 754 binary64 (`double`, `float64`)

- 1 бит знака, 11 бит порядка, 52 бита мантиссы (+ 1 скрытый бит) — 53 значащих двоичных разряда, это
  15–16 десятичных цифр; диапазон $\approx 2{,}2 \cdot 10^{-308} \dots 1{,}8 \cdot 10^{308}$;
- **машинный эпсилон** $\varepsilon_{mach} = 2^{-52} \approx 2{,}22 \cdot 10^{-16}$ — расстояние от 1 до следующего
  представимого числа (`np.finfo(float).eps`);
- **единица округления** $u = \varepsilon_{mach}/2 = 2^{-53} \approx 1{,}11 \cdot 10^{-16}$ — максимальная
  относительная ошибка округления к ближайшему;
- **модель арифметики:** $fl(x \circ y) = (x \circ y)(1 + \delta)$, $|\delta| \leq u$ для $+, -, \times, /, \sqrt{\ }$
  (IEEE 754 гарантирует корректное округление этих операций). FMA ($a \cdot b + c$) выполняется с одним округлением;
- **ulp** (шаг сетки) зависит от порядка числа: на $[1, 2)$ он равен $2^{-52} \approx 2{,}22 \cdot 10^{-16}$,
  на $[2, 4)$ — $4{,}44 \cdot 10^{-16}$, на $[4, 8)$ — $8{,}88 \cdot 10^{-16}$, на $[1/4, 1/2)$ — $5{,}55 \cdot 10^{-17}$;
- для `float32`: $\varepsilon_{mach} = 2^{-23} \approx 1{,}19 \cdot 10^{-7}$ — погрешности были бы на 9 порядков больше.

### 6.2. Источники погрешности

1. **Неустранимая** — погрешность входных данных: $1/3$, $2/3$, $4 + i/9$ округляются уже при формировании $A$
   и $L^{точн}$.
2. **Методическая** (погрешность метода) — у прямых методов **отсутствует**: в точной арифметике метод Холецкого
   даёт точный результат за конечное число операций. Она есть у итерационных методов и у разностных схем —
   поэтому там погрешность с ростом числа узлов убывает, а здесь растёт.
3. **Вычислительная** — ошибки округления в арифметических операциях; у нас она основная.

### 6.3. Неассоциативность сложения

В машинной арифметике $(a + b) + c \neq a + (b + c)$: например, `(0.1 + 0.2) + 0.3 = 0.6000000000000001`,
а `0.1 + (0.2 + 0.3) = 0.6`. Поэтому **результат зависит от порядка суммирования**: размер блока, реализация BLAS
(SIMD, FMA), число потоков, флаги вроде `-ffast-math` меняют последние разряды ответа. Это объясняет, почему
перезапуск на другом компьютере даёт немного другие цифры (см. `README.md`, п. «Перепроверка»).

### 6.4. Погрешность суммирования и скалярного произведения

- последовательное (рекурсивное) суммирование $n$ чисел: $|\hat s - s| \leq (n-1)\,u \sum |x_i| + O(u^2)$;
- скалярное произведение: $|fl(x^T y) - x^T y| \leq \gamma_n\, |x|^T |y|$, где $\gamma_n = \frac{nu}{1 - nu} \approx nu$;
- попарное (каскадное) суммирование: $\approx \lceil \log_2 n \rceil \, u \sum|x_i|$;
- это оценки **сверху** (худший случай). Если ошибки округления ведут себя как случайные, типичная ошибка растёт
  как $\sqrt{n}\,u$;
- блочное суммирование (суммы по $b$ слагаемых, потом сумма $n/b$ частичных сумм) даёт $\approx (b + n/b)\,u$.
  Поэтому блочный алгоритм может быть даже **точнее** точечного. В нашем коде при $N = 1000$: $b = 1$ — погрешность
  $6{,}6 \cdot 10^{-14}$, $b = 4$ — $1{,}3 \cdot 10^{-14}$, $b = 64$ — $8{,}7 \cdot 10^{-15}$ (Linux, OpenBLAS).

### 6.5. Обратный анализ ошибок Уилкинсона: устойчивость метода Холецкого

Если алгоритм дошёл до конца, вычисленный фактор $\hat L$ — точный фактор слегка возмущённой матрицы
(Уилкинсон; в современной форме — Хайэм, «Accuracy and Stability of Numerical Algorithms», теорема 10.3):
$$
\hat L \hat L^T = A + \Delta A, \qquad |\Delta A| \leq \gamma_{n+1} \, |\hat L|\,|\hat L^T| \quad (\text{поэлементно}).
$$
По неравенству Коши — Буняковского $(|L|\,|L^T|)_{ij} = \sum_k |l_{ik}|\,|l_{jk}| \leq \sqrt{a_{ii} a_{jj}}$, поэтому
$|\Delta a_{ij}| \lesssim \gamma_{n+1} \sqrt{a_{ii} a_{jj}}$, а в норме $\|\Delta A\|_2 \lesssim n \gamma_{n+1} \|A\|_2$.
Обратная ошибка мала **независимо от обусловленности** — метод Холецкого обратно устойчив без выбора главного
элемента. (Дополнительно известно, что при не слишком большом $\kappa_2(A)$, грубо при
$n^{3/2} \kappa_2(A)\, u \ll 1$, алгоритм гарантированно не встретит отрицательного подкоренного выражения.)

Невязка из отчёта и есть оценка $\Delta A$. Пример: при $N = 256$ невязка $6{,}4 \cdot 10^{-14}$ при
$\max|a_{ij}| \approx 32{,}3$ — относительная обратная ошибка $\approx 2 \cdot 10^{-15} \approx 9u$, что намного
меньше априорной оценки.

### 6.6. Прямая ошибка

Из теории возмущений для разложения Холецкого: относительная ошибка фактора не превосходит (с точностью до константы)
$\kappa_2(A) \cdot \|\Delta A\| / \|A\|$. Для нашей матрицы $\kappa_2(A) \sim N^2$, так что худшая оценка
$\sim N^3 u$ — при $N = 256$ это порядка $10^{-11}$, а наблюдается $4 \cdot 10^{-15}$. Априорные оценки
мажорантные: они предполагают, что все ошибки округления складываются в одну сторону; на практике они во многом
компенсируют друг друга.

### 6.7. Как объяснить полученный график

- **Плато при малых $N$** ($N = 8, 16$; при перепроверке плато держится для всех $N$ от 2 до 16).
  Максимум погрешности достигается в элементе $L_{11}$: вычислено $1{,}9999999999999998 = 2 - 2^{-52}$ — ближайшее
  к 2 снизу машинное число, т. е. ошибка ровно в один шаг сетки на отрезке $[1, 2)$, $e = 2^{-52} = \varepsilon_{mach}$.
  Причина — округление входного элемента $A_{11} = 4 + 1/9$ и квадрата $(1/3)^2$ под корнем, т. е. неустранимая
  погрешность плюс одно-два округления. Невязка при этом $8{,}88 \cdot 10^{-16} = 2^{-50}$ — один шаг сетки на
  $[4, 8)$, где лежат диагональные элементы $A_{ii} \approx 4$.
- **Рост при больших $N$.** Длина скалярных произведений растёт пропорционально $N$, и накопленная ошибка
  начинает превышать единичное округление. Порядок $p = \log_2(e(2N)/e(N)) \approx 1$ означает $e(N) \sim N u$ —
  это согласуется по порядку с оценкой $\gamma_N \approx N u$ для скалярного произведения длины $N$.
- **Почему $p$ «скачет»** (0,32; 2,00; 0,85 и т. п.). Погрешность — это максимум по $\sim N^2/2$ элементам из
  величин, кратных шагу сетки; при малых ошибках (единицы ulp) переход с 1,25 ε на 5 ε — это уже $p = 2$.
  Надёжен только общий тренд на нескольких точках.

### 6.8. Нормы и порядок роста

- векторные нормы: $\|x\|_1 = \sum|x_i|$, $\|x\|_2 = \sqrt{\sum x_i^2}$, $\|x\|_\infty = \max|x_i|$ (чебышёвская);
- в отчёте использована поэлементная максимум-норма матрицы $\|A\|_{\max} = \max_{i,j}|a_{ij}|$ — это чебышёвская
  норма матрицы, рассматриваемой как вектор из $N^2$ элементов (не путать с операторной нормой $\|A\|_\infty$ —
  максимальной суммой модулей по строкам);
- операторные нормы: $\|A\|_1$ — максимальная сумма модулей по столбцам, $\|A\|_\infty$ — по строкам,
  $\|A\|_2 = \sigma_{\max}(A)$ (для СПО — $\lambda_{\max}$); норма Фробениуса $\|A\|_F = \sqrt{\sum a_{ij}^2}$.
  В конечномерном пространстве все нормы эквивалентны;
- абсолютная и относительная погрешность: $\|L^{точн}\|_{\max} = 2$, поэтому относительная погрешность — это
  абсолютная, делённая на 2;
- в двойном логарифмическом масштабе степенной закон $e = C N^p$ — прямая с наклоном $p$:
  $\log e = \log C + p \log N$; по двум точкам при удвоении $N$: $p = \log_2\big(e(2N)/e(N)\big)$.

## 7. Типовые вопросы на защите и короткие ответы

1. **Почему метод Холецкого, а не метод Гаусса?** Матрица СПО: Холецкий требует вдвое меньше операций
   ($N^3/3$ против $2N^3/3$), вдвое меньше памяти (нижний треугольник) и устойчив без выбора главного элемента.
2. **Что будет, если матрица не СПО?** На каком-то шаге подкоренное выражение станет $\leq 0$; программа выдаст
   ошибку «Матрица не является положительно определённой».
3. **Почему не нужен выбор главного элемента?** $|l_{ik}| \leq \sqrt{a_{ii}}$ — роста элементов нет; обратная ошибка
   ограничена $\gamma_{n+1}|L||L^T|$, а это $\leq \gamma_{n+1}\sqrt{a_{ii}a_{jj}}$ (п. 6.5).
4. **Сколько операций и как это получено?** $\sum_j (j-1)(N-j+1) \approx N^3/6$ умножений и столько же сложений,
   всего $\approx N^3/3$ (п. 2).
5. **Что такое блочное скалярное произведение?** $\sum_{k<j} L_{ik} L_{jk}^T$ — сумма произведений блоков $i$-й и
   $j$-й блочных строк; по сути произведение матриц $b \times jb$ и $jb \times b$ (п. 4.2).
6. **Меняет ли блочность число операций?** Нет, $\approx N^3/3$; меняется порядок вычислений и обращений к памяти.
7. **Зачем тогда блоки?** Локальность: на блок из кэша приходится $O(b)$ операций (BLAS-3), а в точечном алгоритме —
   $O(1)$ (п. 4.5). Это пригодится на этапе 2; на этапе 3–4 блоки задают «зерно» параллелизма.
8. **Почему $b = 4$?** На этапе 1 проверяется правильность, а не скорость. Маленький $b$ даёт много блоков
   (при $N = 256$ — 64 блока по каждой размерности) и хорошо проверяет блочную логику. Оптимальный $b$ подбирается
   на этапе 2 по размеру кэша.
9. **А если $N$ не делится на $b$?** Последний блок меньше (границы блоков считаются через `min`). Проверено
   автотестами ($N = 7, 129$, $b = 3, 16, 200$ и др.).
10. **Как проверяли правильность?** (1) аналитически известное решение $L^{точн}$; (2) невязка $LL^T - A$;
    (3) сравнение с LAPACK (`numpy.linalg.cholesky`) на случайных СПО-матрицах; (4) автотесты `uv run pytest`.
    Любая ошибка в индексах дала бы погрешность порядка единицы, а не $10^{-15}$.
11. **Почему погрешность растёт с $N$? Это ошибка метода?** Нет, методической погрешности у прямого метода нет.
    Растёт вычислительная погрешность: длина скалярных произведений $\sim N$, ошибки округления накапливаются (п. 6.7).
12. **Почему при $N = 8$ и $16$ погрешность одна и та же и равна $\varepsilon_{mach}$?** Это один шаг сетки в элементе
    $L_{11} = 2 - 2^{-52}$, вызванный округлением $4 + 1/9$ (п. 6.7).
13. **Чем погрешность отличается от невязки?** Погрешность — прямая ошибка (нужно точное решение), невязка — обратная
    (можно посчитать всегда). Погрешность $\lesssim \kappa \cdot$ невязка.
14. **Почему на другом компьютере цифры немного другие?** Сложение неассоциативно; NumPy вызывает BLAS, а порядок
    суммирования и использование FMA зависят от библиотеки и процессора (п. 6.3). Порядок величин и выводы те же.
15. **Что такое машинный эпсилон? Единица округления?** $\varepsilon_{mach} = 2^{-52}$ — расстояние от 1 до следующего
    числа; $u = 2^{-53}$ — максимальная относительная ошибка одного округления.
16. **Почему в тестовой матрице $1/3$ и $1/9$?** Они не представимы в двоичной системе — возникают реальные ошибки
    округления; на «удобных» числах погрешность была бы нулевой.
17. **Какая у матрицы обусловленность?** $\kappa_2(A) \sim N^2$: от 3,2 при $N = 8$ до 917 при $N = 256$
    (таблица в п. 5) — матрица хорошо обусловлена.
18. **Какие формы алгоритма Холецкого вы знаете? Какая у вас?** Шесть ijk-форм (п. 3). У нас блочная jik
    (left-looking, через скалярные произведения), внутри диагонального блока — ijk.
19. **Что такое left-looking и right-looking?** Left-looking — при вычислении столбца $j$ «смотрим влево» на уже
    готовые столбцы и применяем отложенные модификации. Right-looking — после вычисления столбца $k$ сразу
    модифицируем всё, что правее и ниже (немедленные модификации).
20. **Что в вашем алгоритме можно делать параллельно?** Все поддиагональные блоки $L_{ij}$ одного блочного столбца;
    модификации $\tilde A_{ij}$ (включая диагональную) — до факторизации $L_{jj}$; слагаемые блочного скалярного
    произведения — с редукцией. Внешний цикл по $j$ — последовательный (п. 4.6).
21. **Как решить СЛАУ, имея $L$?** $Ly = f$, затем $L^T x = y$ — по $N^2$ операций (п. 2).
22. **Что будет во `float32`?** $\varepsilon_{mach} \approx 1{,}2 \cdot 10^{-7}$ — погрешности порядка $10^{-7} \dots 10^{-5}$,
    характер зависимости от $N$ тот же.
23. **Почему выбрана максимум-норма?** Она показывает худший элемент и проста для интерпретации (сравнение
    с $\varepsilon_{mach}$); для другой нормы порядок роста был бы тем же (нормы эквивалентны).
24. **Как растёт время работы?** Как $O(N^3)$: удвоение $N$ — в 8 раз дольше. В Python при малых $N$ время
    определяется накладными расходами интерпретатора ($O(p^3)$ итераций циклов), поэтому для измерения скорости
    нужен компилируемый язык (этап 2). Для ориентира: $N = 1000$, $b = 4$ считается около 4 с.
25. **Почему разложение называют «методом квадратного корня»?** Из-за извлечения корня при вычислении
    диагональных элементов $l_{jj}$.
