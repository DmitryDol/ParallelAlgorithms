## Запуск

Из корня репозитория (зависимости ставит `uv`):

```bash
uv run python lab1_python/cholesky_ref.py
```

Без аргументов воспроизводятся размерности из отчёта ($N = 8 \dots 256$, $b = 4$). Если на сдаче попросят другие
размерности или размер блока ($N$ не обязано делиться на $b$):

```bash
uv run python lab1_python/cholesky_ref.py --sizes 10 50 100 500 1000 --block-size 8
```

Параметры: `-n/--sizes` — список $N$, `-b/--block-size` — размер блока, `-o/--out-dir` — куда сохранить
`cholesky_error.png` и `errors.csv` (по умолчанию `lab1_python/results/`). Для ориентира: $N = 1000$ при $b = 4$
считается около 4 секунд.

Автотесты:

```bash
uv run pytest
```

## Перепроверка (28.10.2026)

**Вывод: реализация корректна, формулы и псевдокод отчёта соответствуют коду, выводы отчёта подтверждаются.**

Что проверено:
1. **Тестовая матрица.** Выкладки отчёта ($(LL^T)_{ii} = 4 + i/9$, $(LL^T)_{ij} = 2/3 + \min(i,j)/9$) верны;
   численно $\max|L^{точн}(L^{точн})^T - A| < 10^{-12}$.
2. **Алгоритм** — именно блочный метод через блочные скалярные произведения: left-looking, блочная форма jik
   (для каждого блочного столбца $j$: $\tilde A_{jj} = A_{jj} - \sum_{k<j} L_{jk}L_{jk}^T$ → точечный Холецкий;
   для $i > j$: $\tilde A_{ij} = A_{ij} - \sum_{k<j} L_{ik}L_{jk}^T$ → $L_{ij} = \tilde A_{ij} L_{jj}^{-T}$).
   Структура совпадает с эталонной LAPACK `dpotrf` для нижнего треугольника.
3. **Вспомогательные процедуры:** `cholesky_point` (точечная ijk-форма через скалярные произведения) и
   `solve_triangular_right` (прямая подстановка для $X L_{jj}^T = B$) проверены на случайных данных.
4. **Сравнение с LAPACK** (`numpy.linalg.cholesky`) на случайных СПО-матрицах:
   $N \in \{1, 2, 3, 5, 7, 10, 17, 33, 50, 64, 100, 129\}$, $b \in \{1, 2, 3, 4, 5, 8, 16, 64, 200\}$, в том числе
   $N$, не кратное $b$, и $b > N$. Максимальное относительное расхождение — $5{,}3 \cdot 10^{-16}$.
5. **Повторный запуск исходного `1.py`** (Linux, Python 3.14, NumPy 2.5 с OpenBLAS):

   | $N$ | погрешность (отчёт) | погрешность (перепроверка) | невязка (отчёт) | невязка (перепроверка) |
   |---|---|---|---|---|
   | 8 | 2,220e-16 | 2,220e-16 | 8,882e-16 | 8,882e-16 |
   | 16 | 2,220e-16 | 2,220e-16 | 8,882e-16 | 8,882e-16 |
   | 32 | 2,776e-16 | 2,776e-16 | 8,882e-16 | 8,882e-16 |
   | 64 | 1,110e-15 | 8,882e-16 | 3,553e-15 | 3,553e-15 |
   | 128 | 2,220e-15 | 1,776e-15 | 1,954e-14 | 2,487e-14 |
   | 256 | 3,997e-15 | 4,441e-15 | 2,132e-14 | 6,395e-14 |

   При $N \leq 32$ совпадение точное, при $N \geq 64$ отличаются последние разряды. Причина: `@` и `np.dot`
   вызывают BLAS, а порядок суммирования и использование FMA зависят от библиотеки и процессора (у однокурсника —
   Windows и другая сборка BLAS). Порядок величин, характер графика и выводы отчёта не меняются. Если преподаватель
   запустит программу на своём компьютере и цифры немного разойдутся с отчётом — это нормально
   (см. `THEORY.md`, п. 6.3).

Что изменено в коде (сами вычислительные функции не тронуты):
- `1.py` переименован в `cholesky_ref.py` — так программа названа в отчёте;
- добавлены параметры командной строки `--sizes`, `--block-size`, `--out-dir`;
- график и CSV сохраняются в `results/`, а не в текущий каталог;
- порядок роста считается по общей формуле $p = \ln(e_{k+1}/e_k) / \ln(N_{k+1}/N_k)$, при удвоении $N$ это тот же
  $\log_2(e(2N)/e(N))$; поэтому таблица на графике корректна и для произвольных $N$, а нулевая погрешность её не ломает;
- таблица порядков на графике перенесена в левый верхний угол — на данных перепроверки она перекрывала кривую;
- в `cholesky_point` добавлена явная проверка: если подкоренное выражение $\leq 0$, выбрасывается `ValueError`
  («матрица не является положительно определённой») вместо молчаливого `NaN`.

Без аргументов программа выдаёт те же числа, что и исходный `1.py`.

## Замечания к отчёту

Ошибок нет; ниже места, о которых могут спросить или которые можно уточнить при желании.
1. **Буква $p$ в двух смыслах:** в разделе «Численный метод» $p = N/b$ — число блоков, а в результатах $p$ —
   порядок роста погрешности. В анализе встречаются оба («$N = 32$ ($p = 8$ блоков…)» и «$p = 0{,}32$»).
   Можно переобозначить порядок роста, например, через $q$.
2. **«Полностью согласуется с теоретической оценкой Уилкинсона».** Оценка Уилкинсона — мажорантная (худший случай)
   и относится прежде всего к обратной ошибке ($\hat L\hat L^T = A + \Delta A$, $|\Delta A| \leq \gamma_{n+1}|L||L^T|$).
   Корректнее: «согласуется по порядку с оценкой $\gamma_N \approx N u$ ошибки скалярного произведения длины $N$».
   Как отвечать, если спросят, — `THEORY.md`, пп. 6.5–6.7.
3. **Плато при $N = 8, 16$** можно объяснить точнее: максимум погрешности — в элементе $L_{11}$, вычисленном как
   $2 - 2^{-52}$ (ровно один шаг сетки), из-за округления $A_{11} = 4 + 1/9$; невязка $8{,}88 \cdot 10^{-16} = 2^{-50}$ —
   один шаг сетки для чисел около 4.
4. **Кэш в таблице характеристик** (L1 256 КБ, L2 1 МБ, L3 8 МБ), по-видимому, взят из диспетчера задач Windows и
   указан суммарно на 4 ядра: на одно ядро это L1d 32 КБ (+ 32 КБ L1i) и L2 256 КБ. На этапе 2 при выборе размера
   блока нужны именно значения на одно ядро.
5. **«Чебышёвская норма»** — здесь это максимум модуля по всем элементам матрицы (чебышёвская норма матрицы как
   вектора из $N^2$ элементов), а не операторная норма $\|\cdot\|_\infty$; если спросят, полезно это различать.
