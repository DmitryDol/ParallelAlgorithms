# Постановка задачи

Рассматривается та же задача, что и в лабораторной работе № 1: разложение Холецкого $A = LL^T$ вещественной симметричной положительно определённой матрицы $A \in \mathbb{R}^{N \times N}$, где $L$ — нижнетреугольная матрица с положительными диагональными элементами. Используется блочный метод Холецкого через блочные скалярные произведения.

Цель этапа — перенести алгоритм на компилируемый язык C++ и исследовать зависимость ускорения вычислений от размерности задачи $N$. Формулировка задания допускает две трактовки ускорения, поэтому исследованы обе:

1. вариант А — ускорение от флага компиляции: одна и та же программа собирается без оптимизации и с оптимизацией, $S_А(N) = T_{\text{без флага}}(N) / T_{\text{с флагом}}(N)$;
2. вариант Б — ускорение блочного алгоритма относительно точечного в одной и той же сборке, $S_Б(N) = T_{\text{точ}}(N) / T_{\text{бл}}(N)$.

## Тестовая задача

Как и на этапе 1, используется матрица с известным точным фактором Холецкого (индексация $i, j = 0, \ldots, N - 1$):

$$L^{\text{точн}}_{ij} = \begin{cases} 2, & i = j, \\ 1/3, & i > j, \\ 0, & i < j, \end{cases} \qquad A_{ij} = \begin{cases} 4 + i/9, & i = j, \\ 2/3 + \min(i, j)/9, & i \neq j. \end{cases}$$

Погрешность вычисляется в чебышёвской норме:

$$e(N) = \max_{0 \leq i, j < N} \left| L^{\text{числ}}_{ij} - L^{\text{точн}}_{ij} \right|.$$

Она выводится при каждом замере, чтобы убедиться, что ускорение не получено ценой потери точности.

# Программная реализация

## Хранение данных и вычислительное ядро

Программа написана на языке C++ (стандарт C++17). Матрицы $A$ и $L$ хранятся одним непрерывным массивом по строкам: элемент $(i, j)$ находится в позиции $i \cdot N + j$. Матрица разбивается на блоки размера $b \times b$, число блоков по каждой размерности $p = \lceil N / b \rceil$; если $N$ не делится на $b$, последний блок неполный.

Блок $\tilde{A}_{ij} = A_{ij} - \sum_{k<j} L_{ik} L_{jk}^T$ вычисляется непосредственно на месте блока $L_{ij}$, после чего к нему применяется точечное разложение Холецкого (при $i = j$) или решение матричного уравнения $L_{ij} L_{jj}^T = \tilde{A}_{ij}$ (при $i > j$). Все операции выполняются собственными циклами, без библиотек BLAS и LAPACK. Основная операция во всех частях алгоритма — скалярное произведение векторов:

```
for (jb = 0; jb < p; ++jb)               // блочный столбец j
  for (ib = jb; ib < p; ++ib) {          // диагональный блок, затем остальные
    At_ij = A_ij;                        // копия на место L_ij
    for (kb = 0; kb < jb; ++kb)          // блочное скалярное произведение
      for (r, c)
        At_ij[r][c] -= dot(L_ik[r], L_jk[c], b);
    if (ib == jb)
      factor_diagonal_block(L_jj);       // L_jj * L_jj^T = At_jj
    else
      solve_lower_transposed(L_ij, L_jj); // L_ij * L_jj^T = At_ij
  }
```

Размерность $N$, размер блока $b$, режим (точечный или блочный) и число замеров задаются из командной строки.

## Точечный алгоритм

Для варианта Б реализован точечный алгоритм в той же форме скалярных произведений (столбец за столбцом):

$$l_{jj} = \sqrt{a_{jj} - \sum_{k<j} l_{jk}^2}, \qquad l_{ij} = \frac{1}{l_{jj}} \left( a_{ij} - \sum_{k<j} l_{ik} l_{jk} \right), \quad i > j.$$

Число операций у обоих алгоритмов одинаково и составляет $\approx N^3/3$; различается только порядок обращений к памяти.

## Методика измерений

Измеряется только время разложения, без формирования матрицы и вычисления погрешности, с помощью `std::chrono::steady_clock`. Первый запуск служит прогревом; если разложение длится меньше 0,05 с, в один замер входит серия разложений и время делится на их число. Для каждой точки выполняется не менее <<repeats>> замеров, а для быстрых разложений — столько, чтобы замеры суммарно заняли не меньше 1 с; в расчётах используется минимальное время. Так кратковременные помехи со стороны других программ не искажают результат. Производительность оценивается как $N^3 / (3T)$ операций с плавающей точкой в секунду. Размерности $N$: <<sizes>>. <<block_choice>>.

## Проверка правильности

Правильность программы проверена автоматическими тестами: точечное разложение блока и решение треугольной системы — на случайных симметричных положительно определённых матрицах; блочный и точечный алгоритмы — на тестовой матрице при $N = 1, 2, 3, 5, 7, 8, 13, 64, 100, 129$ и $b = 1, 2, 3, 4, 8, 16, 200$ (в том числе $N < b$ и $N$, не кратное $b$); отказ на матрице, не являющейся положительно определённой, и на некорректных аргументах командной строки. Кроме того, фактор $L$, найденный программой на C++, поэлементно сравнивался с результатом эталонной программы этапа 1: расхождение не превышает $10^{-13}$ во всех сборках и в обоих режимах.
