## Что нужно получить

- Программу на C++ (стандарт C++17), реализующую **тот же** алгоритм, что и на этапе 1: блочный left-looking метод
  Холецкого через блочные скалярные произведения, тестовую матрицу с известным $L^{точн}$ и ту же метрику
  погрешности $\max|L^{числ} - L^{точн}|$. Все операции — собственными циклами, без BLAS/LAPACK.
- Замеры времени для ряда $N$ и **график ускорения $S(N)$**.

## Открытый вопрос: относительно чего считать ускорение

Формулировка допускает несколько трактовок; **уточнить у преподавателя** (или у тех, кто уже сдал) до начала работы:
1. **Основная:** одна и та же программа, собранная **с флагом и без флага** оптимизации/векторизации:
   $S(N) = T_{\text{без флага}}(N) / T_{\text{с флагом}}(N)$. Например, GCC/Clang: `-O0` против `-O3 -march=native`
   (или `-O3 -fno-tree-vectorize` против `-O3 -march=native`, если интересна именно векторизация);
   MSVC: `/Od` против `/O2 /arch:AVX2`. Это соответствует словам «можно убрать флаг компиляции» и названию
   пособия Головашкина «Векторные алгоритмы…».
2. Блочный алгоритм против точечного (эффект кэш-памяти): $S(N) = T_{\text{точечный}} / T_{\text{блочный}}$.
3. C++ против Python-версии этапа 1. Трактовка слабая: NumPy внутри вызывает скомпилированный BLAS.

Разумный план — сделать программу, которая умеет и точечный, и блочный режим, и мерить её в двух сборках;
тогда любой график из перечисленных строится из одних и тех же данных.

## План реализации (когда этап будет начат)

1. `src/cholesky.cpp` (+ при необходимости `cholesky.hpp`):
   - матрица — один непрерывный массив `std::vector<double>` в построчном порядке (`a[i * n + j]`);
   - функции: генерация тестовой матрицы, точечный Холецкий (ijk), решение $X L_{jj}^T = B$, блочный Холецкий
     через блочные скалярные произведения, вычисление погрешности;
   - параметры командной строки: $N$ (список или диапазон), $b$, число повторов, режим (точечный/блочный);
   - время — `std::chrono::steady_clock`, только для разложения; несколько повторов, в CSV пишется минимум и медиана.
2. `CMakeLists.txt` с двумя конфигурациями (или две цели) — с флагом оптимизации и без; должно собираться и на
   Windows (MSVC или MinGW), и на Linux.
3. Проверка: погрешность на тех же $N$ совпадает по порядку с этапом 1.
4. Подбор $b$: график времени от $b$ при фиксированном большом $N$ (по размеру кэша на ядро; для процессора из
   отчёта L1d = 32 КБ, L2 = 256 КБ — ориентир $b \approx 32 \dots 96$).
5. `plot_speedup.py` (Python + matplotlib через `uv run`) строит график из CSV в `results/` в стиле графика этапа 1.
6. Замеры — на машине, характеристики которой войдут в отчёт; диапазон $N$ — до нескольких тысяч, чтобы матрица
   перестала помещаться в L3 (при $N = 1024$ одна матрица `double` занимает 8 МБ).
