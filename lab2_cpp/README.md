## Что нужно получить

- Программу на C++ (стандарт C++17), реализующую **тот же** алгоритм, что и на этапе 1: блочный left-looking метод
  Холецкого через блочные скалярные произведения, тестовую матрицу с известным $L^{точн}$ и ту же метрику
  погрешности $\max|L^{числ} - L^{точн}|$. Все операции — собственными циклами, без BLAS/LAPACK.
- Замеры времени для ряда $N$ и графики ускорения $S(N)$ — по каждому из двух вариантов ниже.

## Два варианта ускорения (делаем оба)

Формулировка задания допускает разные трактовки (вопросы 1–3 в [README.md](../README.md#вопросы-преподавателю)).
Пока нет ответа преподавателя, оба варианта делаются **по отдельности** — свои замеры, свой CSV, свой график.

**Вариант А — «флаг компиляции».** Одна и та же программа (блочный алгоритм), разные сборки:
$S_А(N) = T_{\text{без флага}}(N) / T_{\text{с флагом}}(N)$.
- основная пара: GCC/Clang `-O0` против `-O3 -march=native`; MSVC `/Od` против `/O2 /arch:AVX2`;
- дополнительная пара, где отличается только векторизация: `-O3 -fno-tree-vectorize` против `-O3 -march=native`;
- если разрешат `-ffast-math` (`/fp:fast`) — ещё одна сборка с ним (векторизация скалярных произведений,
  см. `THEORY.md`, п. 4.4);
- результаты: `results/speedup_flags.csv`, `results/speedup_flags.png`.

**Вариант Б — «блочный против точечного».** Одна программа, два режима: точечный алгоритм (та же форма
скалярных произведений, без блоков) и блочный: $S_Б(N) = T_{\text{точечный}}(N) / T_{\text{блочный}}(N)$.
- замеряется в обеих основных сборках варианта А (с флагом и без);
- дополнительно — время от $b$ при фиксированном большом $N$ (выбор размера блока);
- результаты: `results/speedup_block.csv`, `results/speedup_block.png`, `results/time_vs_block.png`.

Сравнение с Python-версией этапа 1 — не основной результат (NumPy использует скомпилированный BLAS), но при
необходимости строится из тех же данных.

## План реализации (когда этап будет начат)

Порядок работы — по скиллу `lab-mode` (`.claude/skills/lab-mode/SKILL.md`): сначала тест, потом код; граничные
случаи; сверка с этапом 1; журнал решений в конце этого файла.
1. `src/` — вычислительное ядро как чистые функции (без ввода-вывода и таймеров внутри): генерация тестовой
   матрицы, точечный Холецкий (ijk), решение $X L_{jj}^T = B$ по строкам, блочный Холецкий, точечный режим,
   вычисление погрешности. Матрица — `std::vector<double>` в построчном порядке (`a[i * n + j]`).
2. Тесты (CTest): совпадение с аналитическим $L^{точн}$, граничные случаи ($N = 1$, $N < b$, $N$ не кратно $b$,
   $b = 1$, не СПО-матрица, неверные аргументы), сверка $L$ с эталоном этапа 1 для малых $N$ (выгрузка $L$ в файл и
   тест на pytest).
3. Программа замеров: параметры командной строки ($N$, $b$, режим, число повторов); время —
   `std::chrono::steady_clock`, только разложение; в CSV — минимум и медиана, погрешность, сборка.
4. `CMakeLists.txt`: цели для всех сборок варианта А; собирается и в Windows (MSVC или MinGW), и в Linux.
5. Скрипт замеров (проходит по $N$, $b$, режимам и сборкам) и `plot_speedup.py` (Python + matplotlib через
   `uv run`) — графики в стиле этапа 1.
6. Итоговые замеры — на машине из отчёта; $N$ — до нескольких тысяч, чтобы матрица перестала помещаться в L3
   (при $N = 1024$ одна матрица `double` занимает 8 МБ).
