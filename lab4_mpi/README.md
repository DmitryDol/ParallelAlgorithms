# Этап 4 (ЛР №4). Параллельная программа на MPI

> «Полноценная параллельная программа на MPI. Результат: график ускорения, зависимость ускорения от количества потоков.»

Статус: **не начат**. В папке пока только этот план и `THEORY.md` (теория к защите).

## Что нужно получить

- Программу на C++ + MPI с распределением данных между процессами и явным обменом сообщениями, реализующую тот же
  блочный метод Холецкого через блочные скалярные произведения; проверка погрешности — как на этапах 1–3.
- **Графики:** ускорение от размерности $S(N)$ при фиксированном числе процессов и ускорение от числа процессов
  $S(P)$ при нескольких фиксированных $N$. («Потоки» в формулировке — это процессы MPI.)

## План реализации (когда этап будет начат)

Предлагаемая схема (обоснование и оценки — в `THEORY.md`, п. 6):
1. **Циклическое распределение блочных строк:** блочная строка $i$ принадлежит процессу $i \bmod P$. Каждый процесс
   сам генерирует свои строки $A$ по аналитической формуле — рассылать матрицу не нужно.
2. **Шаг $j$:** владелец строки $j$ вычисляет $\tilde A_{jj}$ и $L_{jj}$ (вся строка $j$ у него), затем `MPI_Bcast`
   блочной строки $j$ ($L_{j0}, \dots, L_{jj}$); каждый процесс для своих строк $i > j$ вычисляет
   $\tilde A_{ij} = A_{ij} - \sum_{k<j} L_{ik}L_{jk}^T$ и $L_{ij} = \tilde A_{ij} L_{jj}^{-T}$.
3. **Проверка:** каждый процесс считает погрешность по своим строкам (точное $L$ известно аналитически),
   затем `MPI_Reduce(..., MPI_MAX, ...)` — собирать $L$ на одном процессе не нужно.
4. **Время:** `MPI_Barrier` → `MPI_Wtime()` → разложение → `MPI_Wtime()`; итоговое время — максимум по процессам
   (`MPI_Reduce` с `MPI_MAX`); несколько повторов.
5. **Возможные улучшения** (если останется время): опережающая рассылка внедиагональной части строки $j + 1$
   (перекрытие обменов и вычислений), неблокирующие `MPI_Ibcast`.
6. **Окружение:** Windows — MS-MPI (Microsoft MPI + SDK), запуск `mpiexec -n 4 prog.exe`; Linux — Open MPI или MPICH,
   `mpicxx`, `mpiexec -n 4 ./prog`. Число процессов — не больше числа физических ядер (для Open MPI больше —
   только с `--oversubscribe`).

## Открытые вопросы (уточнить у преподавателя)

1. $T_1$ — время MPI-программы на одном процессе или последовательной программы этапа 2.
2. Нужны ли запуски на нескольких компьютерах (кластер) или достаточно одного многоядерного.
3. Диапазон $P$ (на 4-ядерном процессоре: 1, 2, 3, 4; запуск 8 процессов на 8 логических процессорах можно показать
   отдельно, объяснив эффект Hyper-Threading).
