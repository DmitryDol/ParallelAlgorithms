# Постановка задачи

Рассматривается та же задача, что и в лабораторных работах № 1–3: разложение Холецкого $A = LL^T$ вещественной симметричной положительно определённой матрицы $A \in \mathbb{R}^{N \times N}$, где $L$ — нижнетреугольная матрица с положительными диагональными элементами. Используется блочный метод Холецкого через блочные скалярные произведения.

Цель этапа — написать полноценную параллельную программу для системы с распределённой памятью на основе MPI: распределить данные между процессами, организовать обмены сообщениями и исследовать зависимость ускорения от размерности задачи $N$ и от числа процессов $P$. Ускорение вычисляется в двух определениях, эффективность — по относительному ускорению:

$$S_{\text{отн}}(N, P) = \frac{T_1(N)}{T_P(N)}, \qquad S_{\text{абс}}(N, P) = \frac{T_{\text{посл}}(N)}{T_P(N)}, \qquad E(N, P) = \frac{S_{\text{отн}}(N, P)}{P},$$

где $T_P$ — время программы MPI на $P$ процессах, $T_1$ — время той же программы на одном процессе, $T_{\text{посл}}$ — время последовательной программы этапа 2 (без MPI, с теми же ключами оптимизации).

## Тестовая задача

Как и на этапах 1–3, используется матрица с известным точным фактором Холецкого (индексация $i, j = 0, \ldots, N - 1$):

$$L^{\text{точн}}_{ij} = \begin{cases} 2, & i = j, \\ 1/3, & i > j, \\ 0, & i < j, \end{cases} \qquad A_{ij} = \begin{cases} 4 + i/9, & i = j, \\ 2/3 + \min(i, j)/9, & i \neq j. \end{cases}$$

Погрешность вычисляется в чебышёвской норме:

$$e(N) = \max_{0 \leq i, j < N} \left| L^{\text{числ}}_{ij} - L^{\text{точн}}_{ij} \right|.$$

Она выводится при каждом замере, чтобы убедиться, что ускорение не получено ценой потери точности.

# Программная реализация

## Распределение данных

Вычислительное ядро этапов 2–3 не изменилось: блок $\tilde{A}_{ij} = A_{ij} - \sum_{k<j} L_{ik} L_{jk}^T$ вычисляется на месте блока $L_{ij}$, все операции выполняются собственными циклами (без BLAS и LAPACK), основная операция — скалярное произведение; матрица разбита на $p = \lceil N / b \rceil$ блочных строк. Форма скалярных произведений вычисляет $L_{ij}$ по строкам $i$ и $j$, поэтому данные распределены по блочным строкам: блочная строка $i$ принадлежит процессу $i \bmod P$ (**циклическое распределение**, рис. <<fig:scheme.png>>). Процесс хранит только свои строки $A$ и $L$ — около $N^2 / P$ чисел каждой матрицы — и сам заполняет свои строки $A$ по формуле, поэтому рассылать матрицу не нужно.

!figure scheme.png | Циклическое распределение блочных строк и рассылка строки $j$

Работа над блочной строкой $i$ пропорциональна $i^2$ (у неё $i$ блоков, блок $(i, k)$ требует $k$ блочных произведений). При распределении подряд, по $p / P$ соседних строк, последний процесс получил бы долю $1 - (1 - 1/P)^3$ всей работы — <<block_share>>. При циклическом распределении у каждого процесса есть строки и из начала, и из конца матрицы, и нагрузка выравнивается.

## Алгоритм и обмены

На шаге $j$ строка $j$ нужна всем процессам: $L_{jk}$, $k \leq j$, участвуют в вычислении всех блоков $L_{ij}$, $i > j$. Все блоки $L_{jk}$, $k < j$, вычисляет на предыдущих шагах владелец строки $j$, поэтому строка $j$ к шагу $j$ уже у него. Реализованы две стратегии, которые отличаются порядком рассылок (аналоги стратегий `block` и `phases` лабораторной работы № 3):

```
// block: для каждого столбца j
if (rank == j % P) {                       // владелец строки j
  modify(j, j); factor(j);                 // At_jj и L_jj; остальные ждут
}
MPI_Bcast(строка j: L_j0 ... L_jj, root = j % P);
for (свои i > j) { modify(i, j); solve(i, j); }

// phases: для каждого столбца j
MPI_Bcast(L_j0 ... L_j,j-1, root = j % P);   // известны с прошлых шагов
for (свои i > j) modify(i, j);             // владелец - и modify(j, j)
if (rank == j % P) factor(j);              // последовательно: блок b x b
MPI_Bcast(L_jj, root = j % P);
for (свои i > j) solve(i, j);
```

У стратегии `block` последовательная часть шага — модификация и разложение диагонального блока, доля последовательной работы $\alpha_{\text{block}} \approx 1{,}5\, b / N$; у `phases` модификация $\tilde A_{jj}$ идёт одновременно с остальными, последовательна только факторизация блока $b \times b$, $\alpha_{\text{phases}} \approx b^2 / N^2$, зато рассылок на шаге две (вывод оценок — в отчёте по лабораторной работе № 3).

Строка $j$ рассылается упакованной в непрерывный буфер $[L_{j0} \ldots L_{j,j-1} \mid L_{jj}]$: в памяти владельца её строки идут с шагом $N$, а нужны только первые $(j + 1) b$ столбцов. Вместе с $L_{jj}$ рассылается признак ошибки разложения: отрицательное подкоренное выражение обнаруживает только владелец строки $j$, и, если бы исключение бросал только он, остальные процессы ждали бы его рассылки вечно. По признаку исключение бросают все процессы на одном и том же шаге. Погрешность каждый процесс считает по своим строкам, затем `MPI_Allreduce` с операцией `MPI_MAX` — собирать матрицу $L$ на одном процессе не нужно.

## Объём вычислений и пересылок

На шаге $j$ рассылается $(j + 1) b^2$ чисел, за всё разложение — $\sum_j (j + 1) b^2 \approx N^2/2$ чисел в обеих стратегиях, за $p$ рассылок у `block` и $2p$ у `phases` (таблица <<tab:comm>>). Вычислений — $N^3/3$ операций, то есть на одно пересланное число приходится около $2N/3$ операций. Рассылку получает каждый процесс, поэтому принимаемый процессом объём от $P$ не зависит, а его вычисления уменьшаются как $1/P$: отношение вычислений процесса к его обменам — около $2N / (3P)$. Чем больше $N$, тем меньше доля обменов; с ростом $P$ она растёт.

## Методика измерений

Измеряется только время разложения, без формирования матрицы и вычисления погрешности. Перед каждым замером процессы синхронизируются (`MPI_Barrier`), время измеряется функцией `MPI_Wtime`, а время замера — время самого медленного процесса (`MPI_Allreduce` с `MPI_MAX`). Поэтому все процессы одинаково решают, сколько замеров делать, — иначе часть процессов вызвала бы разложение лишний раз и программа зависла бы на рассылке. Первый запуск служит прогревом; если разложение длится меньше 0,05 с, в один замер входит серия разложений. Для каждой точки выполняется не менее <<repeats>> замеров, а для быстрых разложений — столько, чтобы замеры суммарно заняли не меньше 1 с; в расчётах используется минимальное время. Для каждого числа процессов программа запускается заново командой `mpiexec -n P`. Размерности $N$: <<sizes>>. Числа процессов $P$: <<procs>> — те же, что числа потоков в лабораторной работе № 3. <<block_choice>>.

## Проверка правильности

Правильность проверена автоматическими тестами. Без MPI проверяются вычислительное ядро (на тестовой и случайных матрицах, при $N = 1, 2, 3, 5, 7, 8, 13, 64, 100, 129$ и $b = 1, 2, 3, 4, 8, 16, 200$), распределение блочных строк (каждая строка матрицы — ровно у одного процесса) и главное для MPI свойство: блоки, вычисленные по упакованной строке $j$, побитно совпадают с вычисленными на месте. Под `mpiexec` при $P = 1, 2, 3, 4, 7$ проверяется, что в обеих стратегиях фактор $L$, собранный со всех процессов, **побитно** совпадает с последовательным — в том числе когда процессов больше, чем блочных строк ($N = 10$ и $40$ при $b = 16$), и когда $P$ не делит $p$ ($N = 129$, $b = 16$); что повторное разложение даёт тот же результат; что при не положительно определённой матрице исключение бросают все процессы, а не только владелец блока. Четыре намеренно внесённые ошибки (треугольные решения до рассылки $L_{jj}$, владелец строки — всегда процесс 0, без рассылки признака ошибки, своя строка $j$ среди строк ниже $j$) обнаруживаются тестами. Кроме того, фактор $L$ обеих программ поэлементно сравнивался с результатом эталонной программы этапа 1 (расхождение не превышает $10^{-13}$), а выгрузки $L$ программы MPI при $P = 1, 2, 3, 4, 7$ и последовательной программы совпадают байт в байт.
