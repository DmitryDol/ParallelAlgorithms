## 1. Распределённая память и модель передачи сообщений

- Каждый процесс имеет **своё адресное пространство**; чужую память читать нельзя — данные передаются сообщениями.
  Так устроены кластеры (узлы соединены сетью: Ethernet, InfiniBand), но MPI работает и на одном многоядерном
  компьютере (обмен через общую память).
- **SPMD** (Single Program — Multiple Data): все процессы выполняют одну программу, поведение различается по номеру
  процесса (рангу). MPMD — разные программы.
- Отличие от OpenMP: нет общих переменных, нет гонок данных в привычном смысле, но всё распределение данных и все
  обмены программист задаёт явно; масштабируется за пределы одного компьютера.

## 2. MPI: основы

**MPI (Message Passing Interface)** — стандарт библиотеки передачи сообщений (MPI Forum): MPI-1 (1994), MPI-2
(1997: односторонние обмены, параллельный ввод-вывод), MPI-3 (2012: неблокирующие коллективные операции),
MPI-4 (2021), MPI-4.1 (2023). Реализации: MPICH, Open MPI, Intel MPI, **MS-MPI** (Windows; реализует не весь
MPI-3 — нужные функции проверять по документации).

**Каркас программы:**
```cpp
MPI_Init(&argc, &argv);
int rank, size;
MPI_Comm_rank(MPI_COMM_WORLD, &rank);   // номер процесса 0..size-1
MPI_Comm_size(MPI_COMM_WORLD, &size);   // число процессов
...
MPI_Finalize();
```
Сборка и запуск: `mpicxx prog.cpp -O3 -o prog`, `mpiexec -n 4 ./prog` (Windows + MS-MPI: компоновка с `msmpi.lib`,
`mpiexec -n 4 prog.exe`).

**Коммуникатор** — группа процессов + контекст обмена; `MPI_COMM_WORLD` — все процессы. Новые коммуникаторы —
`MPI_Comm_split` (например, строки и столбцы двумерной решётки процессов).

## 3. Двухточечные обмены

```cpp
MPI_Send(buf, count, MPI_DOUBLE, dest, tag, comm);
MPI_Recv(buf, count, MPI_DOUBLE, source, tag, comm, &status);
```
- «Конверт» сообщения: отправитель, получатель, тег, коммуникатор. `MPI_ANY_SOURCE`, `MPI_ANY_TAG`; фактический
  размер — `MPI_Get_count`.
- Сообщения от одного отправителя одному получателю (в одном коммуникаторе, с одним тегом) не обгоняют друг друга.
- **Блокирующий** `MPI_Send` возвращает управление, когда буфер можно повторно использовать. Короткие сообщения
  обычно буферизуются (eager-протокол), длинные — ждут готовности получателя (rendezvous).
  Режимы: `MPI_Ssend` (синхронный — ждёт начала приёма), `MPI_Bsend` (буферизованный), `MPI_Rsend` (по готовности).
- **Взаимная блокировка (deadlock):** два процесса одновременно делают `MPI_Send` большого сообщения друг другу и
  оба ждут приёма. Решения: разный порядок (чётные сначала отправляют, нечётные принимают), `MPI_Sendrecv`,
  неблокирующие операции.
- **Неблокирующие** `MPI_Isend`, `MPI_Irecv` возвращают `MPI_Request` сразу; завершение — `MPI_Wait`/`MPI_Waitall`/`MPI_Test`.
  Позволяют **перекрывать обмены и вычисления**.

## 4. Коллективные операции

Вызываются **всеми** процессами коммуникатора с согласованными аргументами:
- `MPI_Barrier` — синхронизация;
- `MPI_Bcast` — рассылка от корня всем (дерево: $\lceil \log_2 P \rceil$ шагов);
- `MPI_Scatter(v)` / `MPI_Gather(v)` — раздать части массива / собрать части; `MPI_Allgather` — собрать у всех;
- `MPI_Reduce` / `MPI_Allreduce` — свёртка операцией (`MPI_SUM`, `MPI_MAX`, …) к корню / ко всем;
- `MPI_Alltoall` — каждый каждому; MPI-3: неблокирующие `MPI_Ibcast` и др.

**Производные типы данных:** блок $b \times b$ из матрицы $N \times N$, хранящейся по строкам, описывается как
`MPI_Type_vector(b, b, N, MPI_DOUBLE, &t)` (b кусков по b чисел с шагом N) + `MPI_Type_commit`. Альтернатива — упаковать
данные в непрерывный буфер.

## 5. Модель стоимости обменов

Время передачи сообщения из $m$ байт (модель Хокни): $t = \alpha + \beta m$, где $\alpha$ — латентность
(в общей памяти — доли микросекунды, InfiniBand — 1–2 мкс, Ethernet — десятки мкс), $\beta$ — величина, обратная
пропускной способности. Широковещательная рассылка деревом: $\lceil \log_2 P \rceil (\alpha + \beta m)$; для длинных
сообщений (scatter + allgather) — около $2\beta m$.

Вывод: обмены выгодно делать **редкими и крупными**; эффективность определяется отношением объёма вычислений
к объёму обменов.

## 6. Распараллеливание блочного Холецкого через блочные скалярные произведения

### 6.1. Варианты распределения данных

- **Одномерное блочное (подряд) по строкам** — процесс получает $p/P$ соседних блочных строк. Плохо: работа над
  блочной строкой $i$ пропорциональна $\sim i^2$ (у строки $i$ — $i$ блоков, блок $(i, j)$ требует $j$ произведений),
  поэтому последний процесс получает большую часть работы. При $P = 4$ на последнюю четверть строк приходится
  $1 - (3/4)^3 \approx 58\%$ работы — ускорение не больше $1/0{,}58 \approx 1{,}7$.
- **Одномерное циклическое по строкам** — строка $i$ принадлежит процессу $i \bmod P$. Каждый процесс получает
  строки и из начала, и из конца матрицы — нагрузка сбалансирована.
- **Двумерное блочно-циклическое** (как в ScaLAPACK `pdpotrf`) — решётка процессов $P_r \times P_c$; меньше объём
  обменов при большом $P$, но сложнее реализация.

### 6.2. Предлагаемая схема (циклическое распределение блочных строк)

Форма скалярных произведений вычисляет $L_{ij}$ по **строкам** $i$ и $j$, поэтому распределение по строкам естественно:
```
владелец(i) = i mod P;   каждый процесс генерирует свои строки A сам (формула известна)
for j = 0 .. p-1:
    if rank == владелец(j):
        Ã_jj = A_jj − Σ_{k<j} L_jk L_jkᵀ        // вся строка j — локальная
        L_jj = chol(Ã_jj)
    MPI_Bcast(строка j: L_j0 .. L_jj, root = владелец(j))
    for i > j, i mod P == rank:                  // свои строки, параллельно с другими процессами
        Ã_ij = A_ij − Σ_{k<j} L_ik L_jkᵀ         // L_ik — свои, L_jk — получены
        L_ij = Ã_ij · L_jj⁻ᵀ
```
Почему у владельца строки $j$ уже есть все $L_{jk}$, $k < j$: блок $L_{jk}$ вычисляется на шаге $k$ владельцем строки $j$.

**Оценки** ($\gamma$ — время одной операции с плавающей точкой):
- вычисления на процесс: $\approx \dfrac{N^3}{3P}\gamma$;
- на шаге $j$ рассылается $(j+1)b^2$ чисел, всего $\sum_j (j+1) b^2 \approx N^2/2$ чисел ($4N^2$ байт);
  время обменов $\approx p \lceil\log_2 P\rceil \alpha + \lceil\log_2 P\rceil \beta \cdot 4N^2$;
- отношение «вычисления / обмены» $\sim N/(P \log_2 P)$ — растёт с $N$: чем больше матрица, тем выше эффективность;
  чтобы сохранять эффективность при росте $P$, $N$ нужно увеличивать примерно как $P \log_2 P$ (функция изоэффективности);
- память на процесс: свои строки $A$ и $L$ ($\approx N^2/P$ чисел каждая) + буфер для принятой строки ($b \times N$).

**Последовательная часть и простои:** пока владелец строки $j$ считает $\tilde A_{jj}$ и $L_{jj}$, остальные ждут.
**Улучшение (опережающая рассылка):** внедиагональную часть строки $j$ ($L_{j0}, \dots, L_{j,j-1}$) владелец знает
уже в конце шага $j - 1$ — её можно разослать сразу; тогда остальные процессы считают свои $\tilde A_{ij}$ (им не нужен
$L_{jj}$) одновременно с факторизацией диагонального блока, а потом получают только $L_{jj}$ ($b^2$ чисел).
Ещё сильнее помогает неблокирующая рассылка `MPI_Ibcast` с перекрытием вычислений.

**Проверка:** каждый процесс сравнивает свои строки с аналитическим $L^{точн}$, затем `MPI_Reduce(MPI_MAX)` — собирать
всю матрицу не нужно. Результат совпадает с последовательным побитно: порядок операций в каждом блоке тот же.

## 7. Ускорение и масштабируемость

- $S_P = T_1 / T_P$, $E_P = S_P / P$ (подробнее — теория ЛР 3, п. 4). В MPI к последовательной доле добавляется время
  обменов: $T_P \approx \dfrac{T_1}{P} + T_{посл} + T_{обм}(P)$. Поскольку $T_{обм}$ растёт с $P$, у $S(P)$ при
  фиксированном $N$ есть максимум, после которого добавление процессов замедляет программу.
- **График $S(P)$** при нескольких $N$: для больших $N$ кривая ближе к прямой $S = P$; для малых $N$ рано выходит на
  насыщение (или $S < 1$).
- **График $S(N)$** при фиксированном $P$: растёт с $N$ и стремится к $P \cdot E$.
- Процессов больше, чем физических ядер: процессы делят ядра, ускорение не растёт или падает
  (на 4 ядрах с Hyper-Threading 8 процессов дают мало). Open MPI по умолчанию не запустит процессов больше, чем
  ядер, без `--oversubscribe`.

**Замер времени:** `MPI_Barrier`, затем `MPI_Wtime()` до и после разложения; время программы — максимум по процессам
(`MPI_Reduce` с `MPI_MAX`); разрешение таймера — `MPI_Wtick()`; несколько повторов.

## 8. MPI и OpenMP

| | OpenMP | MPI |
|---|---|---|
| память | общая | распределённая |
| единица параллелизма | поток | процесс |
| обмен данными | через общие переменные | явные сообщения |
| основная опасность | гонки данных, false sharing | взаимные блокировки, объём обменов |
| масштабируемость | одно многоядерное устройство | кластер из многих узлов |
| трудоёмкость | директивы к последовательному коду | перепроектирование программы и данных |

Гибридный подход: MPI между узлами + OpenMP внутри узла.
