## 1. Распределённая память и модель передачи сообщений

- Каждый процесс имеет **своё адресное пространство**; чужую память читать нельзя — данные передаются сообщениями.
  Так устроены кластеры (узлы соединены сетью: Ethernet, InfiniBand), но MPI работает и на одном многоядерном
  компьютере (обмен через общую память).
- **SPMD** (Single Program — Multiple Data): все процессы выполняют одну программу, поведение различается по номеру
  процесса (рангу). MPMD — разные программы.
- Отличие от OpenMP: нет общих переменных, нет гонок данных в привычном смысле, но всё распределение данных и все
  обмены программист задаёт явно; масштабируется за пределы одного компьютера.

---

## 2. MPI: основы

**MPI (Message Passing Interface)** — стандарт библиотеки передачи сообщений (MPI Forum): MPI-1 (1994), MPI-2
(1997: односторонние обмены, параллельный ввод-вывод), MPI-3 (2012: неблокирующие коллективные операции),
MPI-4 (2021), MPI-4.1 (2023). Реализации: MPICH, Open MPI, Intel MPI, **MS-MPI** (Windows; реализует не весь
MPI-3 — нужные функции проверять по документации).

**Каркас программы:**
```cpp
MPI_Init(&argc, &argv);
int rank, size;
MPI_Comm_rank(MPI_COMM_WORLD, &rank);   // номер процесса 0..size-1
MPI_Comm_size(MPI_COMM_WORLD, &size);   // число процессов
...
MPI_Finalize();
```
Сборка и запуск: `mpicxx prog.cpp -O3 -o prog`, `mpiexec -n 4 ./prog` (Windows + MS-MPI: компоновка с `msmpi.lib`,
`mpiexec -n 4 prog.exe`).

**Коммуникатор** — группа процессов + контекст обмена; `MPI_COMM_WORLD` — все процессы. Новые коммуникаторы —
`MPI_Comm_split` (например, строки и столбцы двумерной решётки процессов).

## 3. Двухточечные обмены

```cpp
MPI_Send(buf, count, MPI_DOUBLE, dest, tag, comm);
MPI_Recv(buf, count, MPI_DOUBLE, source, tag, comm, &status);
```
- «Конверт» сообщения: отправитель, получатель, тег, коммуникатор. `MPI_ANY_SOURCE`, `MPI_ANY_TAG`; фактический
  размер — `MPI_Get_count`.
- Сообщения от одного отправителя одному получателю (в одном коммуникаторе, с одним тегом) не обгоняют друг друга.
- **Блокирующий** `MPI_Send` возвращает управление, когда буфер можно повторно использовать. Короткие сообщения
  обычно буферизуются (eager-протокол), длинные — ждут готовности получателя (rendezvous).
  Режимы: `MPI_Ssend` (синхронный — ждёт начала приёма), `MPI_Bsend` (буферизованный), `MPI_Rsend` (по готовности).
- **Взаимная блокировка (deadlock):** два процесса одновременно делают `MPI_Send` большого сообщения друг другу и
  оба ждут приёма. Решения: разный порядок (чётные сначала отправляют, нечётные принимают), `MPI_Sendrecv`,
  неблокирующие операции.
- **Неблокирующие** `MPI_Isend`, `MPI_Irecv` возвращают `MPI_Request` сразу; завершение — `MPI_Wait`/`MPI_Waitall`/`MPI_Test`.
  Позволяют **перекрывать обмены и вычисления**.

## 4. Коллективные операции

Вызываются **всеми** процессами коммуникатора с согласованными аргументами:
- `MPI_Barrier` — синхронизация;
- `MPI_Bcast` — рассылка от корня всем (дерево: $\lceil \log_2 P \rceil$ шагов);
- `MPI_Scatter(v)` / `MPI_Gather(v)` — раздать части массива / собрать части; `MPI_Allgather` — собрать у всех;
- `MPI_Reduce` / `MPI_Allreduce` — свёртка операцией (`MPI_SUM`, `MPI_MAX`, …) к корню / ко всем;
- `MPI_Alltoall` — каждый каждому; MPI-3: неблокирующие `MPI_Ibcast` и др.

**Производные типы данных:** блок $b \times b$ из матрицы $N \times N$, хранящейся по строкам, описывается как
`MPI_Type_vector(b, b, N, MPI_DOUBLE, &t)` (b кусков по b чисел с шагом N) + `MPI_Type_commit`. Альтернатива — упаковать
данные в непрерывный буфер.

## 5. Модель стоимости обменов

Время передачи сообщения из $m$ байт (модель Хокни): $t = \alpha + \beta m$, где $\alpha$ — латентность
(в общей памяти — доли микросекунды, InfiniBand — 1–2 мкс, Ethernet — десятки мкс), $\beta$ — величина, обратная
пропускной способности. Широковещательная рассылка деревом: $\lceil \log_2 P \rceil (\alpha + \beta m)$; для длинных
сообщений (scatter + allgather) — около $2\beta m$.

Вывод: обмены выгодно делать **редкими и крупными**; эффективность определяется отношением объёма вычислений
к объёму обменов.

## 6. Распараллеливание блочного Холецкого через блочные скалярные произведения

### 6.1. Варианты распределения данных

- **Одномерное блочное (подряд) по строкам** — процесс получает $p/P$ соседних блочных строк. Плохо: работа над
  блочной строкой $i$ пропорциональна $\sim i^2$ (у строки $i$ — $i$ блоков, блок $(i, j)$ требует $j$ произведений),
  поэтому последний процесс получает большую часть работы: на последнюю $1/P$ часть строк приходится
  $1 - (1 - 1/P)^3$ работы. При $P = 4$ это $\approx 58\%$ — ускорение не больше $1/0{,}58 \approx 1{,}7$;
  при $P = 12$ — $\approx 23\%$, ускорение не больше $\approx 4{,}4$ вместо 12.
- **Одномерное циклическое по строкам** — строка $i$ принадлежит процессу $i \bmod P$. Каждый процесс получает
  строки и из начала, и из конца матрицы — нагрузка сбалансирована.
- **Двумерное блочно-циклическое** (как в ScaLAPACK `pdpotrf`) — решётка процессов $P_r \times P_c$; меньше объём
  обменов при большом $P$, но сложнее реализация.

### 6.2. Реализованная схема (циклическое распределение блочных строк)

Форма скалярных произведений вычисляет $L_{ij}$ по **строкам** $i$ и $j$, поэтому распределение по строкам естественно.
Две стратегии — аналоги стратегий `block` и `phases` этапа 3:
```
владелец(i) = i mod P;   каждый процесс заполняет свои строки A сам (формула известна)

block: for j = 0 .. p-1:
    if rank == владелец(j):
        Ã_jj = A_jj − Σ_{k<j} L_jk L_jkᵀ        // вся строка j — локальная
        L_jj = chol(Ã_jj)                        // остальные ждут
    MPI_Bcast(строка j: L_j0 .. L_jj + признак ошибки, root = владелец(j))
    for свои i > j:                              // одновременно с другими процессами
        Ã_ij = A_ij − Σ_{k<j} L_ik L_jkᵀ         // L_ik — свои, L_jk — получены
        L_ij = Ã_ij · L_jj⁻ᵀ

phases: for j = 0 .. p-1:
    MPI_Bcast(L_j0 .. L_j,j−1, root = владелец(j))   // известны владельцу с прошлых шагов
    свои Ã_ij, i > j  (владелец — и Ã_jj)            // одновременно
    if rank == владелец(j): L_jj = chol(Ã_jj)        // последовательно — только блок b×b
    MPI_Bcast(L_jj + признак ошибки, root = владелец(j))
    свои L_ij = Ã_ij · L_jj⁻ᵀ
```
Почему у владельца строки $j$ уже есть все $L_{jk}$, $k < j$: блок $L_{jk}$ вычисляется на шаге $k$ владельцем строки $j$.
Строка $j$ рассылается упакованной в непрерывный буфер $[L_{j0} \dots L_{j,j-1} \mid L_{jj}]$ (вместо производного
типа `MPI_Type_vector`): её строки в памяти владельца идут с шагом $N$, а нужны только первые $(j+1)b$ столбцов.

**Ошибка у одного процесса.** Отрицательное подкоренное выражение обнаруживает только владелец строки $j$. Если бы
исключение бросал только он, остальные ждали бы его рассылки вечно (взаимная блокировка). Поэтому признак ошибки
рассылается вместе с $L_{jj}$, и исключение бросают все процессы на одном и том же шаге.

**Оценки** ($\gamma$ — время одной операции с плавающей точкой):
- вычисления на процесс: $\approx \dfrac{N^3}{3P}\gamma$;
- на шаге $j$ рассылается $(j+1)b^2$ чисел, всего $\sum_j (j+1) b^2 \approx N^2/2$ чисел ($4N^2$ байт) — в обеих
  стратегиях; рассылок $p = N/b$ у `block` и $2p$ у `phases`; время обменов
  $\approx p \lceil\log_2 P\rceil \alpha + \lceil\log_2 P\rceil \beta \cdot 4N^2$ (у `phases` — латентность вдвое больше);
- отношение «вычисления / обмены» $\sim N/(P \log_2 P)$ — растёт с $N$: чем больше матрица, тем выше эффективность;
  чтобы сохранять эффективность при росте $P$, $N$ нужно увеличивать примерно как $P \log_2 P$ (функция изоэффективности);
- память на процесс: свои строки $A$ и $L$ ($\approx N^2/P$ чисел каждая) + буфер для принятой строки ($b \times N$).

**Последовательная часть и простои.** У `block`, пока владелец строки $j$ считает $\tilde A_{jj}$ и $L_{jj}$, остальные
ждут: $\alpha \approx 1{,}5\, b/N$, как у стратегии `block` этапа 3. У `phases` модификация $\tilde A_{jj}$ идёт
одновременно с остальными, последовательна только факторизация: $\alpha \approx b^2/N^2$ — ценой второй рассылки на шаге.
К этому добавляется неравномерность: на шаге $j$ строк ниже $j$ всего $p - j - 1$, у процессов их $\lfloor m/P \rfloor$
или $\lceil m/P \rceil$ — та же, что у `schedule(static)` этапа 3. Модель ускорения с этими двумя эффектами, но без затрат
на обмены — `plot_speedup.py::cyclic_model_speedup`; разница между ней и замером — время рассылок и ожидания.
Следующее улучшение — неблокирующая рассылка `MPI_Ibcast` с перекрытием обменов и вычислений.

**Проверка:** каждый процесс сравнивает свои строки с аналитическим $L^{точн}$, затем `MPI_Allreduce(MPI_MAX)` — собирать
всю матрицу не нужно. Результат совпадает с последовательным побитно: порядок операций в каждом блоке тот же, а обе
программы вызывают одни и те же функции ядра.

## 7. Ускорение и масштабируемость

- $S_P = T_1 / T_P$, $E_P = S_P / P$ (подробнее — теория ЛР 3, п. 4). В MPI к последовательной доле добавляется время
  обменов: $T_P \approx \dfrac{T_1}{P} + T_{посл} + T_{обм}(P)$. Поскольку $T_{обм}$ растёт с $P$, у $S(P)$ при
  фиксированном $N$ есть максимум, после которого добавление процессов замедляет программу.
- **График $S(P)$** при нескольких $N$: для больших $N$ кривая ближе к прямой $S = P$; для малых $N$ рано выходит на
  насыщение (или $S < 1$).
- **График $S(N)$** при фиксированном $P$: растёт с $N$ и стремится к $P \cdot E$.
- Процессов больше, чем физических ядер: процессы делят ядра, ускорение не растёт или падает (на компьютере из
  отчёта — 12 ядер и 24 логических процессора; $P = 16, 24$ показывают эффект Hyper-Threading). Open MPI по умолчанию
  не запустит процессов больше, чем ядер, без `--oversubscribe`, а с этим ключом перестаёт привязывать процессы
  к ядрам; MS-MPI ограничений не ставит.

**Замер времени:** `MPI_Barrier`, затем `MPI_Wtime()` до и после разложения; время программы — максимум по процессам
(`MPI_Allreduce` с `MPI_MAX`: время известно всем процессам, и все одинаково решают, сколько замеров делать — иначе
часть процессов вызвала бы разложение лишний раз и программа зависла бы на рассылке); разрешение таймера —
`MPI_Wtick()`; несколько повторов.

## 8. MPI и OpenMP

| | OpenMP | MPI |
|---|---|---|
| память | общая | распределённая |
| единица параллелизма | поток | процесс |
| обмен данными | через общие переменные | явные сообщения |
| основная опасность | гонки данных, false sharing | взаимные блокировки, объём обменов |
| масштабируемость | одно многоядерное устройство | кластер из многих узлов |
| трудоёмкость | директивы к последовательному коду | перепроектирование программы и данных |

Гибридный подход: MPI между узлами + OpenMP внутри узла.

## 9. Типовые вопросы на защите

1. **Чем MPI отличается от OpenMP?** (п. 8)
2. **Что такое коммуникатор, ранг?** (п. 2)
3. **Блокирующие и неблокирующие обмены; когда возникает deadlock?** (п. 3)
4. **Какие коллективные операции вы используете и зачем?** `MPI_Bcast` — рассылка блочной строки $j$ (у `phases` —
   двумя частями); `MPI_Allreduce(MAX)` — погрешность и время замера; `MPI_Barrier` — перед замером (пп. 4, 6, 7).
5. **Как распределены данные? Почему циклически?** Работа над строкой $\sim i^2$; при распределении подряд —
   дисбаланс, $S \leq 1{,}7$ при $P = 4$ и $S \leq 4{,}4$ при $P = 12$ (п. 6.1).
6. **Сколько данных пересылается и сколько считается?** $\approx N^2/2$ чисел против $N^3/(3P)$ операций на процесс (п. 6.2).
7. **Почему при малых $N$ ускорение мало или меньше 1?** Обмены и последовательная часть сравнимы с вычислениями (п. 7).
8. **Почему ускорение перестаёт расти с ростом числа процессов?** Рост $T_{обм}(P)$, последовательная часть, число
   физических ядер (п. 7).
9. **Как можно улучшить алгоритм?** Опережающая рассылка, перекрытие обменов и вычислений, двумерное распределение (п. 6).
10. **Как измеряли время?** Барьер, `MPI_Wtime`, максимум по процессам (п. 7).
11. **Совпадает ли результат с последовательным?** Да, порядок операций в каждом блоке не меняется (п. 6.2).
12. **Что такое модель $\alpha + \beta m$?** (п. 5)
13. **Что такое изоэффективность, сильная и слабая масштабируемость?** (п. 6.2; теория ЛР 3, п. 4)
14. **Чем стратегия `phases` отличается от `block`?** Внедиагональная часть строки $j$ рассылается сразу, модификация
    $\tilde A_{jj}$ идёт вместе с остальными, последовательна только факторизация $L_{jj}$; цена — две рассылки
    на шаге вместо одной (п. 6.2).
15. **Что будет, если матрица не положительно определена?** Ошибку видит только владелец строки $j$; признак
    рассылается вместе с $L_{jj}$, и исключение бросают все процессы — без взаимной блокировки (п. 6.2).
16. **Почему строка $j$ упаковывается, а не рассылается производным типом?** Нужны первые $(j+1)b$ столбцов строк
    с шагом $N$; упаковка $O(N b)$ копирований на шаг — пренебрежимо мало по сравнению с $O(N^2 b)$ операциями
    шага, а буфер сразу имеет вид, удобный для вычислений (пп. 4, 6.2).
17. **Зачем программа на одном процессе, если есть последовательная?** Это $T_1$ относительного ускорения;
    сравнение с $T_{посл}$ показывает накладные расходы MPI (упаковка, пустые рассылки) — они малы (п. 10).

## 10. Что получилось в нашей реализации

Числа — компьютер из отчёта (Xeon E5-2678 v3, 12 ядер / 24 логических процессора, Windows 11, MSVC 19.51,
MS-MPI 10.1, $b = 12$), 05.11.2026. Подробнее — `README.md`, раздел «Результаты».

- **Проверка.** При $P = 1, 2, 3, 4, 7$ фактор $L$ побитно совпадает с однопроцессным и с последовательной
  программой, обе стратегии — побитно между собой; погрешность — та же, что на этапе 3 при том же $b$.
- **Ускорение** `block` при $N = 3000$: 3,79 ($P = 4$), 6,20 ($P = 8$), 7,19 ($P = 16$); `phases` — 3,86, 6,33, 7,71;
  `phases` быстрее при всех $N$. При малых $N$ рассылки и последовательная часть сравнимы с вычислениями:
  при $N = 100$ ускорение не больше 1,43.
- **Модель без обменов** при $P \leq 4$ выше замера не больше чем на 8 %; закон Амдала по $P \leq 4$ даёт у `block`
  $\alpha$ = 7,0 / 2,4 / 1,7 % ($N = 1000 / 2000 / 3000$) против 3,7 / 1,9 / 1,3 % у модели: избыток — время рассылок,
  и он быстро убывает с ростом $N$, как и предсказывает отношение «вычисления / обмены» $\sim N/(P \log_2 P)$.
- **MPI против OpenMP** (этап 3, тот же компьютер): при $N = 3000$ и $P \leq 4$ — одинаково (2 %), при $P = 8$ MPI
  медленнее на 12 %, при $N = 1000$ ускорение MPI ниже на 3–7 % — копирование сообщений через общую память и ожидание
  рассылок; при $P \geq 8$ оба упираются в 16–26 GFLOP/s.
- **$P = 24$:** обвал при малых $N$ (в 33 раза медленнее при $N = 100$): процессов столько же, сколько логических
  процессоров, MS-MPI ждёт сообщений активным опросом, и вытесненный процесс задерживает рассылку на каждом шаге.
  Вывод для практики: процессов MPI с активным ожиданием — не больше числа ядер. Проверка 09.11.2026 (фоновые программы закрыты): обвал не воспроизводится, $P = 23$ и $P = 24$
  одинаковы, а $P = 12$ даёт ускорение 10,6 — как модель; значит, в прогоне замеров процессы вытесняла внешняя
  нагрузка (другие программы), которой при всех занятых логических процессорах деваться некуда. Числа этого
  раздела будут обновлены после перезамера.
