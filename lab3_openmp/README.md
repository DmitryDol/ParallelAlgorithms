# Этап 3 (ЛР №3). OpenMP: автоматическое распараллеливание

> «Используем OpenMP. Используем лишь автоматическое распараллеливание. Результат: график зависимости ускорения.»

Статус: **не начат**. В папке пока только этот план и `THEORY.md` (теория к защите).

## Что нужно получить

- Программу этапа 2, распараллеленную средствами OpenMP **без ручного распределения работы**: только директивы
  распараллеливания циклов (`#pragma omp parallel for` и т. п.), распределение итераций по потокам делает
  среда выполнения. Алгоритм, тестовая матрица и проверка погрешности — те же, что на этапах 1–2.
- **График ускорения** $S(N) = T_1(N) / T_P(N)$ для нескольких чисел потоков $P$ (например, 2, 4, 8).

## Открытые вопросы (уточнить у преподавателя)

1. **Что значит «лишь автоматическое распараллеливание».** Основная трактовка: распараллеливание циклов директивами
   OpenMP (`parallel for`), без ручного разбиения работы по `omp_get_thread_num()`, без задач (`task`) и явной
   синхронизации. Альтернатива: автоматическое распараллеливание компилятором (`-ftree-parallelize-loops=P` в GCC,
   `/Qpar` в MSVC), которое внутри использует ту же среду выполнения OpenMP.
2. **Что брать за $T_1$:** время той же OpenMP-программы на одном потоке или время лучшей последовательной
   программы этапа 2. Если не уточнят — показать оба и явно подписать.
3. Строить ли дополнительно $S(P)$ при фиксированном $N$ (на этапе 4 это требуется явно).

## План реализации (когда этап будет начат)

1. Взять код этапа 2 (скопировать в `lab3_openmp/src/`, чтобы этап 2 остался в сданном виде).
2. Распараллелить цикл по блочным строкам $i > j$ (поддиагональные блоки независимы) директивой
   `#pragma omp parallel for schedule(static|dynamic)`; временные блоки объявлять внутри тела цикла (private).
3. Варианты для сравнения: одна параллельная область вокруг цикла по $j$ с `#pragma omp for` внутри и `single`
   для диагонального блока; вынос модификации диагонального блока в общий параллельный цикл (см. теорию, п. 5).
4. Проверка: результат должен **побитно совпадать** с последовательной версией (порядок операций внутри
   каждого блока не меняется) — погрешность та же, что на этапе 2.
5. Замеры: `omp_get_wtime()`, число потоков — через `OMP_NUM_THREADS` или аргумент командной строки; $N$ — до
   нескольких тысяч; CSV в `results/`, график — `plot_speedup.py`.
6. Сборка: GCC/Clang `-O3 -march=native -fopenmp`; MSVC `/O2 /openmp` (OpenMP 2.0: индекс цикла — знаковый `int`)
   или `/openmp:llvm`; в CMake — `find_package(OpenMP)` и `OpenMP::OpenMP_CXX`.
