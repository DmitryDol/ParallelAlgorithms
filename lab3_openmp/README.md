# Этап 3 (ЛР №3). OpenMP: автоматическое распараллеливание

> «Используем OpenMP. Используем лишь автоматическое распараллеливание. Результат: график зависимости ускорения.»

Статус: **не начат**. В папке пока только этот план и `THEORY.md` (теория к защите).

## Что нужно получить

- Программу этапа 2, распараллеленную без ручного распределения работы между потоками. Алгоритм, тестовая
  матрица и проверка погрешности — те же, что на этапах 1–2.
- **Графики ускорения:** $S(N)$ для нескольких чисел потоков $P$ (2, 4, 8) и $S(P)$ при нескольких фиксированных $N$.

## Варианты (делаем все по отдельности)

Трактовка задания не однозначна (вопросы 4–5 в [README.md](../README.md#вопросы-преподавателю)). Пока нет ответа
преподавателя, каждый вариант — отдельная сборка со своими замерами, CSV и графиком.

**Что значит «автоматическое распараллеливание»:**
- **Вариант А — директивы OpenMP над циклами.** `#pragma omp parallel for` на цикле по поддиагональным блокам
  (итерации независимы), распределение итераций делает OpenMP; без `omp_get_thread_num()`-разбиения, задач и
  ручной синхронизации. Результаты: `results/omp_*.csv`, `results/omp_*.png`.
- **Вариант Б — автопараллелизация компилятором.** Код этапа 2 без директив, собранный с GCC
  `-ftree-parallelize-loops=P` (или MSVC `/Qpar`); компилятор сам решает, какие циклы распараллелить. Обязательно
  сохранить его отчёт о том, что распараллелено (GCC — `-fdump-tree-parloops-details`, MSVC — `/Qpar-report:2`):
  если распараллелено мало, это тоже результат, его нужно объяснить. В GCC число потоков, по-видимому, задаётся
  при компиляции — проверить при реализации; если так, на каждое $P$ — своя сборка. Результаты:
  `results/autopar_*.csv`, `results/autopar_*.png`.

**Относительно чего считать ускорение** (для обоих вариантов строятся обе кривые):
- относительное: $S^{отн}_P = T_1 / T_P$, где $T_1$ — та же программа на одном потоке;
- абсолютное: $S^{абс}_P = T_{посл} / T_P$, где $T_{посл}$ — лучшая последовательная сборка этапа 2 (с флагом
  оптимизации, без OpenMP).

## План реализации (когда этап будет начат)

Порядок работы — по скиллу `lab-mode` (`.claude/skills/lab-mode/SKILL.md`).
1. Скопировать код этапа 2 в `lab3_openmp/src/`, чтобы этап 2 остался в сданном виде.
2. Вариант А: `parallel for` по блочным строкам $i > j$; временные блоки объявлять внутри тела цикла (private).
   Для сравнения внутри варианта А — одна параллельная область вокруг цикла по $j$ с `#pragma omp for` и `single`
   для диагонального блока, а также вынос модификации диагонального блока в общий параллельный цикл
   (`THEORY.md`, п. 5).
3. Вариант Б: сборка кода этапа 2 с ключами автопараллелизации; отчёт компилятора — в `results/`.
4. Сверка: при любом $P$ результат совпадает **побитно** с той же программой на одном потоке, с этапом 2 — до
   округления; граничные случаи $P > p$ и $P$, не делящее $p$.
5. Замеры: `omp_get_wtime()`, число потоков — через `OMP_NUM_THREADS` или аргумент командной строки; $N$ — до
   нескольких тысяч; скрипт замеров пишет CSV в `results/`, графики — `plot_speedup.py`.
6. Сборка: GCC/Clang `-O3 -march=native -fopenmp`; MSVC `/O2 /openmp` (OpenMP 2.0: индекс цикла — знаковый `int`)
   или `/openmp:llvm`; в CMake — `find_package(OpenMP)` и `OpenMP::OpenMP_CXX`.
